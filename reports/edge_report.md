## 엣지 vs 클라우드 도입 판정 결과

**과제**: 제품 생산성 증진을 위한 진동 기반 불량률 판단 및 제어 시스템

| 판정 축 | 기준 수치 및 분석 내용 | 판정 결과 |
|---|---|---|
| **1. 실시간성 (Latency)** | 클라우드 약 2,000ms vs 엣지 약 200ms. 본 과제는 단순 '판단'에 그치지 않고 '제어(설비 정지/조정)'까지 포함하는 폐루프(closed-loop) 제어 시스템임. 진동 이상 감지 후 2초의 지연은 불량품이 이미 다수 생산된 이후에나 대응이 이루어짐을 의미하여 생산 라인 제어 목적상 치명적(Critical) 지연으로 판단됨. 200ms 수준의 엣지 응답은 실시간 제어 루프 요구사항에 부합. | **[엣지]** |
| **2. 오프라인 (Connectivity)** | 공장 설비 제어 시스템은 네트워크 순단·혼잡 상황에서도 생산 라인이 멈추지 않고 지속적으로 불량 판정/제어가 이루어져야 함. 클라우드 의존 시 네트워크 장애가 곧 생산 중단 리스크로 직결되므로, 상시 접속을 전제로 할 수 없는 산업 제어 환경 특성상 오프라인 대응 필요성이 높음. | **[엣지]** |
| **3. 프라이버시 (Privacy)** | 진동 센서 데이터 자체는 개인정보가 아니나, 특정 설비의 진동 패턴은 생산 공정 노하우(불량 임계값, 공정 파라미터 등) 유추가 가능한 산업 기밀 성격을 가질 수 있음. 단, 제시된 [참고 사항]에 별도의 기밀성 등급 명시가 없어 '치명적' 수준으로 단정하기는 어려움 (중간 수준으로 평가). | **[엣지]** (보수적 판단, 근거 약함) |
| **4. 모델 크기 (Model Size)** | 진동 데이터 기반 이상탐지/분류는 시계열 센서 데이터를 다루는 경량 분류 모델(FFT+CNN, LSTM, Autoencoder 등)로 충분히 구현 가능하며 LLM급 초거대 모델이 불필요함. SLM/엣지 AI 칩(NPU 등)으로 구동 가능한 전형적 산업 엣지 AI 사례. | **[엣지]** |
| **5. 호출량 및 비용 (Traffic/Cost)** | 클라우드: 10,000 calls/월 × $0.001 = **$10/월**. 엣지: HW $1,300 + 전력 $200 = **$1,500/월**. 순수 비용 관점에서는 클라우드가 약 150배 저렴하여 클라우드가 압도적으로 유리함. (단, 이 비용 비교는 저트래픽 상황이므로 비용만 놓고 보면 엣지 도입 명분은 약함) | **[클라우드]** |

---

### 종합 요약

5개 축 중 **4개 축(실시간성/오프라인/프라이버시/모델크기)이 엣지로 판정**되어 엣지 유력 조건(3개 이상)을 충족하며, 특히 **'실시간성'이 생산 제어 관점에서 치명적(Critical) 요소**로 작용해 최종 판정 규칙상 엣지가 명확히 우세합니다. 비용 측면(호출량/트래픽)만 클라우드가 유리하지만, 이는 불량 발생으로 인한 생산 손실 비용을 고려하지 않은 단순 API 호출 비용 비교이므로 전체 판정을 뒤집을 만한 요인은 아닙니다.

### 🎯 최종 추천: **[ 엣지 유력/필수 ]**

**핵심 근거**: 진동 기반 불량 "판단 + 제어"는 2초의 클라우드 지연을 감내할 수 없는 실시간 폐루프 시스템이며, 경량 모델로 충분히 구현 가능하고, 네트워크 장애 시에도 생산 라인이 정지되어서는 안 되는 특성상 엣지 도입이 필수적입니다. 다만 저트래픽 구간(10,000 calls/월)에서는 엣지 HW/전력 비용($1,500)이 순수 클라우드 비용보다 높으므로, 초기 도입 시에는 **하이브리드 아키텍처**(실시간 제어는 엣지, 장기 트렌드 분석·모델 재학습은 클라우드)를 검토하는 것이 비용 효율 측면에서 권장됩니다.
