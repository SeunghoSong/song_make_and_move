
# 📌 [PRD] 하이브리드 AI 기반 스마트 강의실 자동 출랙/출석 관리 시스템

---

## 1. 문제 정의 (Problem Statement)

### 1.1. 현재 상황 및 프로세스

* 교수가 수업 시작 시간에 물리적/전자 출석부를 확인하며 수동으로 수강생 이름을 호명함.
* 수강생은 호명 시 대답하고, 교수는 출석 상태(`출석`, `지각`, `결석`, `공결`)를 일일이 수기 또는 강의관리시스템(LMS)에 기록함.

### 1.2. 기존 방식의 한계 및 문제점

* **호명 및 청취 오류 (Human Error)**: 교수가 호명을 누락하거나, 웅성거림으로 학생의 대답을 못 듣거나, 학생이 본인 이름을 듣지 못해 출석이 누락되는 문제 발생.
* **시스템/환경 의존성 결함**: 학교 LMS 서버 장애, 교수 계정 로그인 실패, 교수의 지각 등 돌발 변수 발생 시 출석 확인 자체가 불가능함.
* **동명이인 및 유사 이름 혼동**: 동명이인 또는 음운이 유사한 이름으로 인해 타인의 출결이 잘못 기록되는 인적 실수 빈번.
* **부정/대리 출석 문제**: 지인이나 대리인이 호명에 대신 대답하는 부정을 원천 차단하기 어려움.

### 1.3. 해당 제품이 해결하려는 핵심 가치 및 AI 도입 필요성

* **하이브리드 2차 교차 검증 (Dual Verification)**: `CCTV 비전 AI(1차 안면 인식)`와 `학내 Wi-Fi 연결 + QR 앱 인증(2차 재확인)`을 결합하여 대리 출석 및 오인식률을 0%에 가깝게 차단.
* **Zero-Time 출석 체크**: 호명 시간을 제거하여 1회 강의 당 약 10~15분의 수업 시간을 보장.
* **데이터 증강(Augmentation) 기반 높은 인식률**: 학생부 DB의 단일 정면 사진을 AI로 다양각도(Yaw/Pitch/Roll) 증강 생성 후 Vector DB화하여, 강의실 내 비정형 자세에서도 정교하게 식별.

## 2. 사용자 시나리오 (User Scenario)

```
[1단계: 정보 수집 동의 & Vector DB 구축]
       │
       ▼
[2단계: 강의 20분 전 CCTV 다중 안면 자동 감지] ──► [미인식 발생 시] ──► 교수/행정실 알림 & 
       │                                                                QR 예외 인증 처리
       ▼
[3단계: 학내 Wi-Fi + 출석 앱 실행 (2차 교차 재확인)]
       │
       ▼
[4단계: 출석관리 시스템 판정 & 실시간 상태 조회]
       │
       ▼
[5단계: 교수의 최종 재량 수정 & 이력 관리]

```

* **1단계 (초기 설정 및 데이터 학습)**
* 학생은 최초 출석 앱 접속 시 개인정보(얼굴) 수집 동의 및 본인 인증(앱 재설치 시 포함)을 진행함.
* AI 시스템은 학생부 DB의 기존 프로필 사진을 추출하여 3D Pose 및 다양한 각도의 프로필을 시뮬레이션·증강한 뒤, 이를 Vector DB(임베딩)로 변환 및 저장함.


* **2단계 (1차 비전 AI 감지 - 강의 20분 전)**
* 수업 시작 20분 전부터 강의실 CCTV가 작동하여 입실하는 학생들의 다중 안면 데이터를 실시간 수집 및 수강자 명단과 1:1 Matching을 진행함.


* **3단계 (2차 모바일 교차 확인 - 학생 입실)**
* 학생이 강의실에 들어와 **학교 공식 Wi-Fi에 연결 후 출석 앱을 실행**하면, 엣지 AI 인식 결과와 디바이스 식별 정보(MAC/UUID)가 결합하여 2차 재확인이 완료됨.


* **4단계 (예외 처리 및 예외 QR 인증)**
* 안면 인식이 실패했거나 조명/가림으로 미인식된 학생의 경우, 교수 대시보드 및 행정실로 미인식 알림 및 사진이 공유되며, 학생은 **앱 내 생성된 일회성 dynamic QR코드**를 교수에게 제시해 정식 출석을 인증받음.


* **5단계 (출석 확정 및 관리자 제어)**
* 최종 판단 결과(입실 시간 포함)가 출석 관리 시스템에 자동 반영됨. 교수는 시스템 결과를 확인한 후 재량에 따라 수동으로 `출석`, `지각`, `결석`, `공결`을 원클릭 변경·확정할 수 있음.

| **2. 정확성** | **1. 이상 기기 탐지 수** | **월 0건 (목표)** | Wi-Fi 테더링 또는 MAC 주소 변조 등 대리 출석 시도 감지 건수 |
|  | **2. 수동 수정 수** | **전체 출석의 3% 미만** | AI 처리 결과 후 교수가 직접 클릭하여 수동 보정한 횟수 |
|  | **3. 출석 오류 수** | **0.5% 미만** | 최종 확정 후 수강생 이의 제기에 의해 정정된 출결 오류 건수 |
| **3. 기술 안정성** | **1. 피크타임 서버 안정률** | **99.9% (SLA)** | 수업 시작 직전(매시 50분~00분) 서버 가동률 |
|  | **2. 서버 응답 속도** | **500ms 이내** | 앱 접속/QR 검증/Wi-Fi 체킹 시 API Latency |
|  | **3. 서버 장애 발생률** | **0.01% 이하** | 전체 처리 시도 건수 대비 서버 5xx 에러 발생 비율 |
|  | **4. 앱 크러시(Crash)율** | **0.1% 이하** | 출석 전용 모바일 앱의 강제 종료 비율 |
| **4. 사용자 편의성** | **1. 출석 성공률 (1인당 시도 횟수)** | **평균 1.05회** | 1인당 출석 완료까지 앱 실행 및 QR 제시를 시도한 횟수 |
|  | **2. 프로세스 문제 발생률** | **1.0% 미만** | Wi-Fi 미연결, 앱 미설치 등으로 수동 인증으로 전환된 비율 |
|  | **3. 총 출석 소요시간** | **0초 (Zero-Time)** | 기존 수동 호명(10~15분 소요) 대비 수업 시간 유실 단축 시간 |

## 5. 개발 범위 / 비범위 (Scope)

### 개발 범위 (In Scope)

* **영상 수집 및 엣지 AI 전처리**: 강의실 CCTV RTSP 연동, ROI 영역 설정 및 디노이징.
* **학생부 DB 연동 & Face Data Augmentation**: 정면 사진 데이터 3D 각도 변환 및 Vector DB 구축.
* **다중 안면 인식 & 2차 모바일 교차 검증**: 비전 AI 탐지 + 학내 Wi-Fi BSSID 확인 + 기기 고유값 체킹.
* **비상/예외 수동 인증 (QR)**: 안면 미인식 시 1회성 변동 QR을 통한 교수 직접 승인 파이프라인.
* **사용자 본인 인증 및 보안**: 앱 최초 실행/재설치 시 SMS/PASS 본인 인증 및 개인정보 동의 처리.
* **출석 상태 자동 관리 (출석/지각/결석/공결)**: 조건별 자동 판정 및 당일 출석 현황 관리.
* **교수 및 학생용 출석 대시보드**: 실시간 출석 확인, 출석 시간 기록 조회, 교수 재량 수동 보정 기능.

### 개발 제외 범위 (Out of Scope)

* **기타 위치 추적 기술 (GPS, BLE Beacon 등)**: Wi-Fi 및 Vision 데이터 외의 위치 센서 모듈 제외.
* **강의실 공간 스케일링/구조 보정**: 소형/대형 등 강의실 규모에 따른 카메라 하드웨어 자동 제어 알고리즘 제외.
* **학기 전체 누적 출석/성적 산출 관리**: 당일/개별 강의 출석 처리에 집중하며, 성적 연동 관리 기능은 제외.
* **수강 신청 및 강좌 수강생 등록 시스템**: 학사 관리 시스템(LMS)과의 DB 연동에만 의존하며 직접 구현 제외.
* **교수용 수업 자료/시간표 관리 시스템**: Pure 출석 관리에 집중하며 LMS 자체 관리 기능은 범위 제외.
